## §1 Review findings (architect, 2026-09-29)

### 1.1 Balance (headless sweep: `npm run balance`, N=30 all-bot matches per difficulty, 10 animals)
Baseline win rates (win% / avg placement, lower placement = better):

| Animal | L1 | L2 | L3 | L4 |
|---|---|---|---|---|
| giraffe | 37% / 1.8 | 57% / 2.3 | **67% / 2.0** | **47% / 3.0** |
| hippo | 63% / 2.0 | 23% / 3.2 | 0% / 6.8 | 10% / 6.0 |
| lion | 0% / 4.3 | 7% / 4.9 | 3% / 5.2 | 7% / 4.6 |
| gorilla | 0% / 4.5 | 3% / 5.6 | 3% / 6.0 | 17% / 4.3 |
| crocodile | 0% / 5.2 | 0% / 6.6 | 0% / 4.2 | 3% / 5.3 |
| eagle | 0% / 5.4 | 0% / 6.3 | 3% / 4.9 | 10% / 5.4 |
| rhino | 0% / 6.5 | 0% / 6.0 | 7% / 5.2 | 3% / 5.6 |
| python | 0% / 9.0 | 10% / 5.8 | 13% / 5.6 | 3% / 8.2 |
| panther | 0% / 8.0 | 0% / 6.2 | 0% / 7.5 | 0% / 6.1 |
| mole | 0% / 8.4 | 0% / 8.3 | 3% / 7.4 | 0% / 6.5 |

Match length: L1 ≈ 38 s, L2 ≈ 60 s, L3 ≈ 163 s, L4 ≈ 154 s (bloodlust starts at 120 s, so L3/L4 matches often hit it). **Findings:** giraffe (4.0 m reach, 140° arc) wins almost everything — a range monopoly; panther/mole/python (the "assassin" and "skill" animals) almost never win, even at L4 where their scripted combos should shine, so part of this is bot-script weakness, not only numbers. Target after tuning: at L3 and L4 (N≥60) every animal between ~4% and ~18% win rate; at L1/L2 no animal above ~30%.

### 1.2 Graphics (visual review via screenshots)
Good: readable low-poly stadium, crowd, silhouettes recognizable. Weak: flat/plain sand floor, no post-processing (no bloom/vignette/tonemapping/grade), no torches/fire/dust/light shafts, animals are crude (lion has stick legs and a floating mane sphere, no eyes/faces worth the name, little surface detail), damage numbers are huge and stack in one blob at screen center, spectate camera sits almost on the ground, camera pull-in near the wall (player spawns at r=24 so a 6.5 m boom reaches r=30.5, behind the wall) makes the close-quarters view unreliable. Perf headroom is large: measured 11–14 draw calls, ~39k tris (budgets 150 / 120k).

### 1.3 UI/UX bugs and gaps
Ability icons in the HUD bottom-right are blank dark circles (special + ultimate show no glyph or key label). No enemy nameplates/health bars in a 10-fighter melee, no lock-on/aim assist for mouse-aimed melee, no incoming-damage direction indicator. Settings has no graphics-quality option.

### 1.4 Distribution
No desktop build exists. Request: an installable Windows desktop app that can be downloaded and played locally, with **version history**. Interpretation: (a) semver + `CHANGELOG.md` as the single source of truth, (b) an in-game "Version History / What's New" panel driven by that changelog, (c) versioned installer artifacts (`Gladiator-Kingdom-Setup-<version>.exe` + portable zip) built by electron-builder and published per tag via GitHub Releases so every past version stays downloadable, (d) notify-only update check.

## §3 WP-J — Gameplay & Balance
**Owns:** `src/sim/**`, `src/ai/**`, `src/config/**`, `tests/**`, `scripts/balance-sweep.ts`, `docs/BALANCE.md`, and the §8 table in `docs/BLUEPRINT.md` (keep it in sync with config). Does not touch `src/render`, `src/ui`, `src/match`, `src/input`, `package.json`.

Goals, in priority order:
1. **Rebalance to the §1.1 targets** using `npm run balance` (N=60+, LEVELS=3,4 for the primary target; also confirm L1/L2). Diagnose root causes before turning knobs: why giraffe reach dominates (bots at all levels can't close/kite it? arc too wide? swing recovery too short for the reach?), and why panther/mole/python underperform (stat numbers vs weak bot scripts in `src/ai/scripts.ts` — fix the scripts if they're the cause). Keep each animal's real-animal identity and blueprint archetype (tank/bruiser/assassin/reach/control); keep DPS bands roughly comparable so UI stat pips stay honest — update `statPips`, lore lines and ability description strings in `config/animals.ts` when numbers change (UI reads them live).
2. **Ultimate/special economy.** Measure per-match ult casts and special casts per fighter at L3/L4 (add a stat readout to the balance script if useful). Target ~1–2 ultimates per fighter per match at L3/L4 (currently they are likely rare because charge comes only from landed basics). Preferred lever: a small ult-charge gain from damage *taken* (e.g. 25–30% of the landed-hit gain rate, unaffected by block) so losing fighters still get comeback ults; document in `balance.ts`. Do not make ults trivially spammable.
3. **Player-facing fairness.** A human plays with mouse aim and human latency: verify with a test that an L1 Cub bot cannot kill an idle full-HP fighter in under ~15 s of fight time at L1, and that L1 average match time stays 35–60 s. If L1/L2 are too punishing/too passive for a human, retune the profile params in `config/botProfiles.ts` (never add stat cheats).
4. **Bug hunt in sim/AI** while you are in there (stuck bots against pillars/walls, bots ignoring pickups, targets never re-acquired, timeouts): add a regression test per real bug found.
5. Write `docs/BALANCE.md`: method, before/after table (all four levels), the reasoning per animal changed, and known remaining imbalances.

Acceptance: `npm run balance` at N=60 shows the §1.1 target bands for L3 and L4 (report the final tables); 0 timeouts; `npx vitest run` green (existing tests updated only where config numbers legitimately changed; determinism test still passes); tsc clean; BLUEPRINT §8 synced.

## §4 WP-K — Graphics
**Owns:** everything under `src/render/**` (including `render/animals/**`, `preview.ts`, `Effects.ts`, `Stadium.ts`, `SceneManager.ts`, `CameraRig.ts`, `crowd.ts`, `geo.ts`, demos). Does not touch sim/ai/config/ui/match/input/package.json (three's `examples/jsm` addons ship inside the installed `three` package — import from `three/examples/jsm/...` or `three/addons/...`, no new dependency).

Goals:
1. **Post-processing + tone**: EffectComposer pipeline (RenderPass → subtle UnrealBloomPass with high threshold so only sun glints, fire, sparks, ult flashes bloom → vignette + gentle warm color-grade pass → OutputPass with ACES filmic tone mapping + sRGB). Add quality tiers `'low' | 'medium' | 'high'`: low = no composer (renderer direct, cheap), medium = composer without bloom-heavy extras, high = everything. API on SceneManager: `setQuality(q)`, `getQuality()`, and an auto mode that samples frame time and drops one tier if avg fps < 45 for 3 s (never raises again in the same session). Read initial setting from `localStorage['gk-quality']` (`'auto'|'low'|'medium'|'high'`, default `'auto'` starting at high). The UI toggle comes later (WP-M) — expose everything it needs.
2. **Arena upgrade** (all from `config/arena.ts` geometry): procedural canvas-generated sand texture (fine grain, ripples, faint tracks) + inlaid arena ring/emblem in the center, better wall/stands materials (subtle color variation, trim), **torches** on pillars/gates/wall with flickering flame sprites/particles and at most 4 real point lights (rest are emissive glow), god-ray style light shafts (cheap additive cones), drifting dust motes, waving banners (vertex or scale animation), richer sky (gradient + soft clouds), crowd polish (more color variety, occasional waving flags). Keep draw calls ≤ 250 and tris ≤ 250k at the high tier; the low tier should cost about what the current scene costs.
3. **Animal model overhaul (all 10)**: raise detail budget to ~900–1,800 tris each. Real faces (eyes with a dark pupil/glint, nostrils, ears, teeth/tusks/horns/beak), proper proportions (fix the lion: solid legs and a mane wrapped around the head/neck, not a floating sphere), two-tone shading via vertex colors (lighter belly, darker back), markings (giraffe patches, panther sheen + glowing eyes, python scale bands + tongue flicker, croc scutes ridge + jaw teeth, hippo ears/tusks, rhino horn/plates/ear, eagle layered feathers, gorilla silverback saddle, mole claws + star-ish nose), claws/hooves. Add a subtle **inverted-hull outline** on fighters (dark, tinted, scaled by quality: off on low) for stylized readability against sand. **The rig contract is frozen:** `AnimalFactory.create/createRig`, `AnimalRig.update(state, dtRender)`, impact pose at exactly u=0.55 of the swing, all joint animation continues to work — re-verify every action (attack1/2/3, special, ultimate, block, hit, stagger, knockdown, dead, glide, burrowed, grab poses) in `?demo=animals` for all 10.
4. **Effects polish**: nicer hit sparks and impact rings, ground-crack/dust-ring decals for slams (gorilla leap, hippo rush, rhino stampede, giraffe kick), ult auras (colored ring + light column that blooms), improved telegraph decal look, footstep/landing dust, guard-break shatter. **Damage numbers**: size scales with damage (small hits small, finishers/ults larger), randomized offsets + upward drift + stacking so numbers don't blob at screen center, capped max on-screen size, keep the pool at 64.
5. **Camera**: fix the wall problem (a boom that would end outside the wall/behind geometry must shorten smoothly, not snap or clip into the player; consider raising the pivot/pitch slightly near the wall), raise the spectate camera (distance ~8–9 m, pitch ~20°, height clear of the ground), gentle FOV kick on ult/heavy hits, keep the analytic collision approach. Keep `yaw`, `applyMouseDelta`, `follow`, `setSpectate`, `shakeSource` API unchanged.
6. Keep perf: 60 fps on integrated-class GPUs at medium, no per-frame allocations, pool everything.

Acceptance: tsc/tests/build green; `?demo=arena`, `?demo=animals` and a real match render with zero console errors at all three quality tiers; before/after screenshots reviewed by you (1280×720) for the lobby preview, a mid-match view, an ult, and each of the 10 animals; report measured draw calls/tris/fps per tier and the exact public API additions.

4. **In-game Version History panel**: `src/ui/VersionPanel.ts` (+ CSS appended to `ui.css`), opened from a "Version History" / "What's New" button in the Lobby (nav item or footer link). Lists every version newest-first with date, grouped bullets, current-version badge; scrollable; keyboard-closable (Esc/close button). Shown automatically once after an update (compare with `localStorage['gk-last-seen-version']`). Follow the existing gold/stone lobby styling.
5. **Update check (notify-only)**: in the packaged desktop app only, one request to `https://api.github.com/repos/idekakdj/Battle-Royale-v1/releases/latest` a few seconds after launch (main process, 5 s timeout, silent on any failure/404/offline), semver-compare with the running version; if newer, show a lobby banner "Update vX.Y.Z available — Download" that opens the release page via `openExternal`. Setting to disable it (`gk-settings.checkUpdates`, default true — wire into the existing settings panel with a tiny addition). No auto-download, no auto-install.
6. **Installer** via `electron-builder` (devDependencies: `electron`, `electron-builder`; install them — you're the only agent allowed to run `npm install`): NSIS installer (not one-click: choose install dir, per-user install, desktop + Start Menu shortcuts, proper uninstaller, app data preserved on uninstall by default) **plus** a portable `.zip`; artifact names `Gladiator-Kingdom-Setup-${version}.exe` and `Gladiator-Kingdom-${version}-win-x64.zip`; output to `release/` (git-ignored); `appId` `com.gladiatorkingdom.game`; product/company strings; only ship `dist/**` + `electron/**` + package.json (no sources/tests/node_modules bloat, `asar` on). Icons: generate procedurally (crossed swords + laurel on stone/gold, matching the lobby logo) with a committed `scripts/make-icons.mjs` producing `build/icon.png` (512) [+ `.ico` if needed] — no external assets. **Known Windows pitfall:** electron-builder's `winCodeSign` archive can fail to extract without symlink privilege ("A required privilege is not held by the client"). If you hit it, do NOT change system settings; set `win.signAndEditExecutable: false` and apply icon/version metadata yourself in an `afterPack` hook (e.g. the `rcedit` package) so the exe still has the right icon and version info. Installers are unsigned; document SmartScreen behavior and how to add a signing certificate later (env vars) in `docs/RELEASING.md`.
7. **Scripts**: `npm run desktop` (build + launch Electron on `dist`), `npm run desktop:dev` (vite dev server + Electron pointed at it; small node script, no extra deps beyond electron), `npm run dist` (build + NSIS + zip → `release/`), `npm run dist:dir` (unpacked, fast), `npm run release:notes` (prints the changelog section for the current version — used by CI). 
8. **GitHub Actions** `.github/workflows/release.yml`: on tag `v*.*.*` — checkout, node 20, `npm ci`, typecheck + test, `npm run dist`, create a GitHub Release named after the tag with the changelog section as the body and attach the installer + zip (use `softprops/action-gh-release` or `gh release create`), on `windows-latest`. Leave the existing Pages workflow alone (keep `base: './'` working for both).
9. `docs/RELEASING.md`: exact steps to cut a release (edit changelog → bump version → commit → tag → push tag), where the versioned installers appear, how old versions stay downloadable (Releases), how players install/uninstall/update, SmartScreen note. README "Desktop app" section.
